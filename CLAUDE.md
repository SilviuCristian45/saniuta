## Project

"Săniuța la vale": browser multiplayer top-down sled race down a mountain slope (Carpathians, sunset/night, wooden sleds), between fir trees, rocks, ramps and snowballs. npm workspaces monorepo: `shared/` (pure deterministic simulation), `client/` (Phaser 3 + Vite), `server/` (authoritative Colyseus 0.18). README and user-facing strings are in Romanian; code comments are in English. Requires Node ≥ 22.12.

Architecture follows the `multiplayer-colyseus` skill; deploy follows the `vps-deploy` skill. Reference projects, **read only, never modify**:

## Commands

Run from the repo root:

```bash
npm install
npm run dev          # client (http://localhost:5175) + server (:2570) together; dev:client / dev:server for one
npm test             # vitest for /shared, the client's DOM-free modules (client/test), the server tests
npm run typecheck    # tsc for shared + client + server
npm run build        # client/dist (static) + server/dist/index.js (single esbuild bundle, no node_modules needed)
npm run sim -- --bots usor,mediu,greu,greu --rounds 3 --track 1 --seed abc -v   # headless bots-only match, prints every run + standings
npm run balance -- --matches 20 --lineup usor,usor,mediu,mediu,greu,greu --track all   # bot tournament per track: points, wins, finish %, times, crashes, hits, power-ups used (--powerups off; --set key=value,... tries TUNING values)
```

Single test file / test name:

```bash
npm test -w shared -- test/rng.test.ts
npm test -w shared -- -t "<test name substring>"
npm run test:watch -w shared
```

## Architecture

### `/shared` — deterministic simulation (no Phaser, no DOM)
- Consumed as raw TypeScript (`exports` → `src/index.ts`); no build step.
- **Determinism is a hard rule**: no `Date.now()`, `performance.now()`, `new Date`, `Math.random()`, float trig, `**`. Randomness goes through the seeded mulberry32 RNG whose state lives in the game state (`rng.ts`). Same seed + same inputs ⇒ byte-identical state.
- **Fixed-point**: every position, velocity, angle and timer is an integer. Angles are integer steps (`ANGLE_STEPS` = 1024) with a literal sine table (`fixed.ts`: `isin`/`icos`/`iatan2`/`isqrt`/`idiv` (never -0)/`hash32`/`percent`). **Never use bitwise operators on fixed-point values**; bitwise is allowed only in `rng.ts`/`fixed.ts`/`roomCode.ts` on uint32 words. `test/sourceRules.test.ts` enforces this.
- Fixed tick: 30/s (`TICK_RATE`). One `runTick(state, inputs)` (inputs + bot decisions + `step`) runs identically in `LocalTransport`, client prediction and on the server.
- Flat state (`players: Record<id, PlayerState>`, number arrays, fixed slots instead of object lists) so it maps onto `@colyseus/schema`. **A new state field goes into `stateKeys.ts` (`GAME_STATE_KEYS` scalars, `GAME_ARRAY_KEYS` number arrays, `PLAYER_STATE_KEYS`) and `server/src/schema.ts`**; `test/netcode.test.ts` checks the lists against `createGameState`/`addPlayer`. Players are always iterated with `sortedPlayers` (slot order), collision pairs in that order.
- World axes: x right, y down the slope (the race goes toward +y). Angles: 0 = +x, `DOWNHILL` = 256 = +y; the heading stays within `MAX_HEADING_OFFSET` (~105°) of downhill. **Steering is screen-relative: steer > 0 goes toward +x, which lowers the heading.** Input per tick: `{ seq, steer, throttle, fire, use? }` (`steer`/`throttle` integers in -100..100; throttle > 0 = kick "sus", < 0 = brake "jos"; `fire` (throw) and `use` (power-up) latched until the next tick; `InputQueue` carries both over from dropped inputs).
- `tuning.ts`: the riding-feel numbers physics reads at run time (`TUNING`, defaults `DEFAULT_TUNING` from `constants.ts`). **Only the local `?tune` panel may change `TUNING`**; a test asserts the defaults. To adopt tuned values, change `constants.ts` and re-run `npm run balance` + the balance test.
- Modules:
  - `powerups.ts` (stage 7, `GameState.powerUps`, lobby option `setPowerUps`, on by default): gift boxes (`track.gifts`, lines of 3 across the track every ~48 rows, generated **after** everything else so the older layout stays byte-identical; `giftTimers`, back after `GIFT_RESPAWN_TICKS`) give one power-up (`PlayerState.powerUp`, at most one, only with empty hands) drawn with `nextInt(state)` from odds interpolated by the place (`placePerMille`: 0 leader .. 1000 last; `POWER_ODDS_FIRST`/`_LAST`, catch-up). `usePowerUp` on a `use` press (not while overturned): Ceară `waxTicks` (push + half friction, cap raised, fading over `WAX_FADE_TICKS`: `speedCap`), Ceai `tea` (`overturn()` in physics.ts spends it instead of overturning: grace ticks + 'shield' event; lasts the run), Bulgăre uriaș (`launchGiant`: a `BALL_GIANT` in the ball slots, `ballKind`; rolls with gravity, bounces off the snowbank, overturns grounded sleds it touches (`OBSTACLE_GIANT` crash), never the thrower, breaks on obstacles), Fular `scarfTicks` (snowballs fall apart: 'shield'), Ceață `fogTicks` on every other racer (drawn only: no minimap). Everything resets at `startRound`.
  - `track.ts`: **the track is never in the state or on the wire**: `getTrack(trackId, seed)` (cached) builds it with its own RNG (never `GameState.rng`). Rows `ROW_LEN` (32 px) apart with `center`/`half`/`slope` (smooth waypoint series), interpolated between rows (`centerAt`/`halfWidthAt`/`slopeAt`). Obstacles (trees, rocks: discs), ramps (rectangles), snowball piles are bucketed by their center row (`nearby` looks at the row ±1, `itemsBetween` for bots looking ahead); patches of ice/deep snow follow the track (lo/hi in per-mille of the half width) and `surfaceAt` reads them. Generation keeps the start clear, obstacles `minGap` apart and an opening of 6 sled radii across every stretch (`roomFor` checks the whole band; `test/track.test.ts` re-checks every 8 px). `TRACK_DEFS`: "Pârtia Bunicii" (easy), "Valea Lupului" (medium), "Coborârea Nebunilor" (hard), fixed seeds; "Pârtie aleatoare" mixes their parameters and gets a new seed every run (`startRound` draws `trackSeed` from `state.rng`).
  - `physics.ts`: `rideSled` (overturned: no control, heavy friction, gets up pointing downhill with `graceTicks`; in the air: no steering, little drag, landing boost along the heading; riding: steering, gravity × slope, kick only below `pushMaxSpeed`, friction/grip per surface + turn drag + brake, speed cap), `rideFinished` (coasts in the run-out), `keepOnTrack` (snowbank at the edges bounces and costs speed), `hitObstacles` (pushed out; approach ≥ `crashMinSpeed` and not down/grace → overturned `crashTicks`), `tryJump` (fast sled whose center is on a ramp: `airTicks = airTotal` from the speed), `collideSleds` (equal-mass impulse + separation; only both on the snow or both in the air, never finished ones).
  - `snowballs.ts`: piles (`pileTimers` per track pile, back after `PILE_RESPAWN_TICKS`), at most `MAX_SNOWBALLS` carried, throws into `BALL_SLOTS` flat slots (`ballX/Y/Vx/Vy/Ticks/Owner` arrays), a hit sled keeps `ballHitKeepPct` of its speed and gets `splatTicks` (no kicking); balls break on obstacles and the snowbank; the thrower, sleds in the air and overturned ones are never hit.
  - `sim.ts`: `applyInput`, `step` (countdown → `go` → ride/throw → sled collisions → obstacles/ramps/piles/snowbank → finishes (same tick: further past the line first) → snowballs; run ends when everyone is down, `FINISH_GRACE_TICKS` (15 s) after the first finisher (`lastCall`), or at `RUN_TIME_LIMIT_TICKS`; places for the rest by distance; points `POINTS_BY_PLACE` 10/7/5/3/2/1 for finishers, **half of their place's points (rounded down, at least 1) for those still on the way** (`lateFinishPoints`); `results` for `RESULTS_TICKS`, then the next run, or `finished` + `matchEnd`).
  - `match.ts`: lobby/run/match lifecycle as in Bombe (`createGameState`, `addPlayer`, `addBot`, `setTrack`, `setRounds`, `startMatch`, `startRound` (sleds side by side above the start line in a seeded order), `leavePlayer`, `backToLobby`, `computeStandings`: points, wins, best time, slot).
  - `bot.ts`: one procedure, `BOT_PARAMS` per level (reaction interval, lookahead, lanes, clearance, ice/deep costs, ramp/pile bonuses, jumps over what is behind a ramp, brakes when blocked, throw chance/range/angle, mistakes, aim noise). Each decision scores `lanes` lines across the track at the lookahead (half as far when all are blocked) along a two-segment path (a few ticks along the current velocity, all of the air time when flying, then to the target) and steers just enough to close the angle by the next decision. `botThink` is pure (rolls are hashes of `state.rng`, round, decision, slot; never advances the RNG). Each line also pays `sledCost` (Mediu, Greu) for passing where a slower sled ahead will be when it catches up, so a bunched field does not keep rear-ending (this was why Greu missed the 15 s window on Pârtia Bunicii, ~7 bumps a run). Looks far, then half, then a quarter as far when every line is blocked. `aimNoise` is the strongest speed knob (it makes the sled weave); `npm run balance` after any change. Power-ups: `giftBonus` on lines through a gift box, `powerSkill` 0 (Ușor: `powerChance`% of decisions, whatever it holds), 1 (Mediu: at once, the giant snowball once anyone is ahead), 2 (Greu, `wantsPower`: wax on a clear line, giant snowball with a rival ahead in line, scarf only when a snowball is coming or a rival with snowballs is close behind, tea and fog at once). With power-ups on, crashes drop (tea) and winners are ~2–3 s faster; the balance test runs both ways.
  - `runner.ts` (`runTick`, `skipBotRound`), `awards.ts` (from match statistics the simulation keeps in PlayerState: Fulgerul = `topSpeed`, Lunetistul = `hits`, Ținta = `hitsTaken`, Cascadorul = `airTime`, Om de zăpadă = most `crashes`, Sanie de oțel = no crash all match; a "most" award needs a value above zero and not everyone tied), `protocol.ts` (wire contract, `ROOM_NAME`, leaderboard types), `stateKeys.ts` + `netcode.ts` (`InputQueue`, `parseInput`, `Predictor`, as in Mașinuțe), `roomCode.ts`.
- `test/powerups.test.ts`: gift boxes on every track (and the old layout unchanged), pickup rules, catch-up odds, every power-up's effect on exact situations, reset per run, the lobby option, bots keeping/using them per level.
- `test/sourceRules.test.ts` greps the source for banned APIs and for bitwise operators outside `rng.ts`/`fixed.ts`/`roomCode.ts`. Tests build runs with `makeRace` on real tracks and exact physics situations on `flatTrack` (`test/helpers.ts`). `test/netcode.test.ts` runs a server and a predicting client over a simulated 100–150 ms network: a sled braking hard right in front is mispredicted, then the prediction is exact again within a round trip and a few ticks. `test/balance.test.ts`: Greu > Mediu > Ușor on every fixed track. `test/determinism.test.ts` also scans a whole match for `-0` anywhere in the state (the network turns it into 0; inputs are normalized with `|| 0` in `axis`, like `idiv`).

### `/client` — rendering only
- Phaser 3 + Vite, a fixed 1280×720 canvas scaled to fit (`render/layout.ts`). **Two layers, two cameras** (`scenes/GameScene.ts`): everything in the world goes on the world layer (the `addWorld` helper; the main camera follows the player's sled a little ahead down the slope and zooms out with speed), the HUD/minimap/snowfall/dusk tint go on the HUD layer (`addHud`; a second camera that never moves). Objects created with `scene.add.*` must be passed through one of the two helpers, or both cameras draw them.
- Scenes only talk to `GameTransport` (`net/GameTransport.ts`): `setInput` every frame (the transport samples it once per tick, throw presses latched), `send`, `onEvents`, `view()` (poses blended between ticks + snowballs in flight, `net/view.ts`), `connectionStatus()`/`closeReason`, `netStats?()` for `?debug`. `LocalTransport`: fixed-step accumulator (catch-up ≤ 250 ms), bots via `runTick`.
- `ColyseusTransport` (stage 4): the own sled is predicted (`Predictor`: `advance` per client tick, `reconcile` on every server state, `resync` when the page comes back from the background); a correction becomes an offset fading over ~100 ms, snapped when one correction **or the accumulated offset** passes 4 sled radii (after a stall many states land in one frame). The own snowballs fly from the prediction; everything else (other sleds, their snowballs, piles, phases, scores) is drawn `INTERP_TICKS` = 3 behind the newest state on an eased view clock. The run's outcome (finish, place, points) is only from the server. Events about the own sled play when the newest state has their tick, the rest when the drawn state does. Ping every second; no message for 4 s while visible ⇒ the socket is closed so the SDK reconnects (`sdkReconnect.ts` retries at once on coming back; `client/test/sdkReconnect.test.ts` fails if the SDK internals change). `?lag=ms&jitter=ms` (`net/LagLine.ts`) delays both directions. `net/rooms.ts`: `VITE_SERVER_URL` (default `/colyseus`, the Vite proxy in dev; empty = offline-only build), errors become Romanian messages (full / in progress via `GET /rooms/:code`, unknown code, rate limits; unreachable or server full ⇒ "Joacă offline" highlighted). `ui/ConnectionBanner.ts` ("Se reconectează...", then back to the menu with the reason), `ui/Toasts.ts` + `ui/presence.ts` (joined / left / dropped / back / new host).
- Resume after a reload (stage 5, `net/resume.ts`): the reconnection token + room code live in sessionStorage (`saniuta.reconnect`), taken out before every attempt (a failed one is never retried) and cleared on a voluntary leave or an idle-lobby close. `main.ts` `startupRoute`: a saved seat skips the intro and the menu reconnects (`resumeRoom`, then the lobby screen passes straight into the game if it is running); a `?room=` link to another room asks first ("Ieși din jocul curent... ?", `abandonResumableRoom` frees the old seat). The predictor numbers on from the server's `lastSeq`.
- `render/`: `textures.ts` (every picture drawn from code once: sleds per slot with rider, firs, rocks, ramp, pile, snowball, cabin, lamp, glow, gift box, giant snowball, the five power-up icons `TEX.power(kind)`; the touch button gets them as data URLs via `textures.getBase64`), `TrackView.ts` (gift boxes shown only with power-ups on, swaying; the track in chunks of 24 rows with manual culling: ground Graphics with grooming lines, steep shading, ice/deep snow, snowbanks, start/finish; obstacles, ramps, piles; firs, cabins and lamps beside the track from `hash32` of the track seed), `SledView.ts` (shadow, sled scaled up in the air, spin when overturned, blink during grace, snow splat, a scarf of trailing links that flutters, names alternating above/below; an orange glow under waxed runners, a mug riding along with tea, a rainbow scarf and ring with the magic scarf), `Trails.ts` (runner tracks, gaps over jumps/crashes), `Snowfall.ts` (screen-space flakes with parallax), `Minimap.ts` (the whole track as a strip, bends stretched ×3; clouds over it while the own `fogTicks` > 0), `Hud.ts` (run/track, time, place, km/h, snowballs, the power-up box (with "[E]" on desktop) and the effects at work with their bars, standings, countdown "3, 2, 1, HAI!", last-call and finish banners), `ResultsPanel.ts` (between runs, with the leaderboard news of the run: `ui/records.ts`), `Podium.ts` (end of the match: 2-1-3 steps rising, snow confetti in the winner's color, full table with points / runs won / best time, the awards from `ui/awards.ts`, records, "Încă un meci" for the host → lobby of the same room), `fx.ts` (snow bursts, confetti, `turnSpray` out of hard turns at speed, `iceSparks` on ice; rationed per sled, fewer with "Efecte reduse"), `format.ts` (time, km/h; no Phaser).

### `/server` — authoritative Colyseus 0.18
- `src/config.ts`: `HOST`/`PORT` from env (default `127.0.0.1:2570`), `MAX_ROOMS` 20, reconnection 15 s, `MAX_MESSAGES_PER_SECOND` 60, per-IP limits and `RATES`, `ALLOWED_ORIGINS` (production: the duckdns site; outside production localhost **and LAN addresses** too, so a phone on the same Wi-Fi can play against the dev server). Built with `build.mjs` (esbuild) into one ESM file `dist/index.js`.
- `src/app.ts`: `exposedMethods` = create / joinById / reconnect only (no `join`/`joinOrCreate`), CORS for allowed origins without credentials, `GET /health` (internal: Caddy answers 404 from outside), `GET /status` (public `{ok:true}`, the deploy's check through Caddy, rate-limited), `GET /rooms/:code` (`open|full|playing|missing`, since Colyseus says "locked" for both). `src/guard.ts` sits in front of every request and upgrade: client IP only from Caddy's last X-Forwarded-For entry (`clientIp.ts`, IPv6 by /64), Origin check, rate limits (`limits.ts`), WebSockets per IP, a budget for unknown codes; `/csp-report` logs.
- `src/SaniutaRoom.ts`: room code (from `crypto`) = roomId, `setPrivate`, `setFixedTimestep(tick)` **then** `patchRate = null`; every tick: queued inputs (`InputQueue`, one per player per tick) → `runTick` → `mirror` (`mirror.ts`: only changed values, arrays resized to the track's piles) → `broadcastPatch()` → `events` message `{ tick, events }`. Lobby messages call the shared host-checked functions (`rounds`, `track`, `powerUps`, `addBot`, `removeBot`, `botLevel`, `setBotLevel`, `start` → `lock()`, `lobby` → `unlock()`, `skipRound` only for the host while only bots ride). `onDrop` → `allowReconnection(15 s)`, `onReconnect` clears the player's queue, `onLeave` → `leavePlayer`. `PlayerState.idle` ("zzz") set room-side: riding, not finished, no input for `IDLE_TICKS`. A lobby nobody starts closes after `LOBBY_IDLE_MINUTES` (`CLOSE_LOBBY_IDLE`). `src/schema.ts`: the flat schema (every GameState field, number arrays as `ArraySchema`). `src/registry.ts`: live rooms by code and owner IP.
- Leaderboard (stage 6): `src/leaderboard.ts` (tables `runs` + `times` via `src/sqlite.ts`, the skill's `openDb`/`migrate`: only append migrations; each nickname's best time per fixed track, top 15, 30 s cache; `record()` returns `top`/`record` news). The room saves on every `roundEnd` (`runResult`): fixed track only, power-ups off only, ≥ 2 humans who played the run for real (input held in ≥ 30% of their riding ticks after the countdown, not idle: `trackActivity`/`playedForReal`, reset at `roundStart`), only humans who crossed the line and are still there; at most `LEADERBOARD_RUNS_PER_IP_PER_DAY` (200) runs per address a day; then `MSG_RECORDS` to everyone. `GET /leaderboard` (rate-limited) → `{ available, tracks }`. `DB_PATH` (production `/var/lib/saniuta/leaderboard.db`, dev `server/data/leaderboard.db`); a database that does not open means no leaderboard, never a crash.
- Tests (`server/test`, port 2571, `fileParallelism: false`): `room.test.ts` (codes, joins, full/locked, host-only lobby actions incl. track, inputs only from the sender, queue limit, one patch per tick rebuilt exactly by the client (snowballs and piles included), events after their patch, ping, message flood, leaving, reconnection mid-run with seq continuing, idle, room limit, a whole match to the end and back), `security.test.ts` (spoofed IPs, rooms/WebSockets/matchmaking per IP, Origin and CORS, no join without a code, code guessing, crypto codes, lobby idle close, limiters), `leaderboard.test.ts` (ranking, nickname merging, news, which runs count, the room saving a run, no/broken database), `lag.test.ts` (end to end: real server + SDK + `Predictor` over 100/150 ms ±30 ms: the hit on a braking sled is mispredicted, afterwards every correction is zero or a whole tick of riding (timer jitter), and the prediction rides a round trip ahead of the newest state; it fails if the prediction stops replaying unconfirmed inputs).
